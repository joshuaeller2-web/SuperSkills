# Company OS

This is the entry point to Josh's personal agent organization. A skill supplies instructions; it does not start bots, connect private chats or grant permissions.

## Start with the request

- **Help or role lookup:** read `F:/AI/Company OS/QUICK-REFERENCE.md`. For a particular role, search `organization.json`, then read only the matching `roles/<id>.md`. Explain its purpose, manager, expected deliverable and how to use it in the requested program. Link `COMPANY-GUIDE.html` for searchable help or `USER-MANUAL.md` for the full manual. Do not launch an assignment for a help request.
- **A real assignment:** read `F:/AI/Company OS/OPERATING-MANUAL.md` and `POLICY.md`, plus the selected charter and its entry in `F:/AI/Company OS/agent-skills/role-skill-map.json`. Load `company-agent-runtime` for lean context, scope, evidence and handoff, then only the assigned sub-master and minor method needed now. The charter's other shared skills remain the role's domain tools. Default intake goes to Chief of Staff. Establish goal, scope, deliverable and completion evidence; infer routine choices and ask only for missing essential input. Follow the existing assignment register convention. Use only relevant specialists, and assign a different agent to verify changes. If separate verification is unavailable, report UNVERIFIED rather than grading your own work as independent.
- **A new idea:** capture only in the authorized inbox until Josh selects it for execution. Do not create a project just because it was mentioned.
- **A handoff:** save goal, scope, decisions, artifact paths, observed evidence, unresolved issues and the next responsible agent. The receiving program must read the packet; conversation history does not transfer automatically.

If the Company OS folder or requested charter is unavailable, state the missing path and limit the answer to available evidence. Do not invent roles, recreate the organization, or reinstall runtimes automatically.

## Working rules

Keep canonical roles and manuals in Company OS; do not duplicate the organization here. Read selectively rather than loading the entire role catalog into context. Honor the current workspace's instructions and the user's authorization. Role titles confer no authority to send messages, spend money, trade, publish or delete files.

For implementation, record the environment, changed files, exact verification commands and outcomes, withheld changes and next owner. Preserve unrelated work. Do not commit or push without explicit instruction. Separate fresh observations from older reports, simulations and unavailable results.

For platform commands and discovery limits, read [Platform access](references/platforms.md). Consult live configuration before claiming that a bot or recurring routine is active. Do not run or modify a scheduler simply because the user asks for the manual or invokes this skill.
