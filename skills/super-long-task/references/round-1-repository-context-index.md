# Repository context index

For repeated repository exploration, create a bounded index of relevant paths, imports, package/build configuration, components and routes. Record skipped directories, files and time-budget limits. Reuse that index only after checking the current repository revision and changed paths. Do not infer framework or import edges without evidence.

Freshness checking is a corrective addition: the inspected upstream workflow trusts its snapshot until re-import. Do not claim the upstream implementation already enforces its richer documented revision metadata. A snapshot is an aid to navigation, not a substitute for inspecting changed code.
