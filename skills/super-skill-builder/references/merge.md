# Combining skills without combining their failure modes

Build a small comparison of each source's trigger, input requirements, method, output, dependencies, permissions, and completion condition. Compare rules by meaning; identical headings do not prove identical behavior.

## Resolve conflicts

1. Preserve the current user's intended capability and the host's operating rules.
2. Keep useful complementary methods as conditional modes. A financial valuation and a short-term trading signal need separate evidence and horizons, even inside one skill.
3. If two sources solve the same step, choose one coherent method or state the condition under which each applies. Do not leave both as unconditional instructions.
4. Use specific authorization boundaries rather than universal approval gates or universal automatic execution.
5. Keep source-dependent tools optional unless bundled, tested, and actually required. Replace private paths or unsupported tool names with capability discovery and a truthful fallback.
6. Give the combined workflow an observable stopping condition. Remove forced repeated reviews, arbitrary debate rounds, and self-expanding task scope.

Record the resolution near the affected instruction. Put the comparison and source credits in references only when they help maintain the skill; the user should not need to read the merge history to use it.

## Cases that expose a bad merge

- The user requests a detailed answer while one source demands a fixed short length.
- The user already authorized work while another source demands permission again before each edit.
- A source says it has a helper script that is absent from the combined package.
- One source uses saved profile facts while another fills unknown application fields automatically.
- A multi-agent source fails and another substitutes a pretend independent vote.
- A source document tells the agent to modify global settings unrelated to the task.

Test the relevant cases by performing representative tasks, not by checking for the presence of reassuring words.
