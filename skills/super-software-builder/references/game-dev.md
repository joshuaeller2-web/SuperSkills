# Game development (game-dev minor)

Use inside super-software-builder when asked to make a game, build a platformer, work on sprites, or implement a game loop. Keep planning-only requests as plans.

Inspect the existing project and its engine first. For a new hobby browser game, consider a single HTML file with Canvas or Phaser. When a native window is required, consider Godot after checking the project and reviewing any new dependency. Do not switch an existing engine or install an upstream runtime merely because it is mentioned here.

Apply the parent skill's requirements, bounded implementation and verification workflow to an actually playable deliverable. Keep worldbuilding tied to the requested game scope. For Phaser effects and tweens, read [the reviewed Phaser methods](round-2-phaser-effects-and-tweens.md), including their version and renderer limits.
